# anu-agent

مساعد ذكي لأسئلة القبول في **جامعة الإسكندرية الأهلية (ANU)** — يجاوب من محتوى `anu.edu.eg` فقط، ويحط لينك المصدر مع كل إجابة.

يشتغل في مكانين: قسم محادثة في الموقع (أو ويدجت عائم على الموقع الرسمي)، وبوت على فيسبوك ماسنجر — الاتنين على نفس السيرفر ونفس قاعدة المعرفة.

---

## ليه مش شات بوت عادي

المشكلة الحقيقية في بوت جامعة مش إنه يرد، إنه **يرد بمعلومة غلط**. رقم مصاريف مخترع أو حد أدنى للمجموع متهيّألوا إنه فاكره = مشكلة على الجامعة. عشان كده فيه طبقتين حماية:

1. **RAG:** النموذج ما يشوفش غير المقاطع المسترجعة من موقع الجامعة، وممنوع يستنتج من معرفته العامة.
2. **فلتر أرقام بعدي** (`app/prompts.py`): بعد ما الرد يخلص، أي رقم في الإجابة مش موجود حرفياً في المقاطع المسترجعة → الرد كله يتلغي ويتبدل بتحويل لإدارة القبول. البرومبت ممكن يتكسر، الفلتر لأ.

الأسئلة اللي مالهاش إجابة بتتسجل في `data/unanswered.jsonl` — دي أهم مخرجات المشروع، لأنها بتقولك المحتوى الناقص على الموقع.

## التشغيل

```bash
git clone https://github.com/khaled-dotcom/anu-agent.git
cd anu-agent

python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env      # وحط مفتاح Groq — راجع GUIDE-TOKENS.md
python scripts/ingest.py  # يسحب محتوى الموقع ويبني قاعدة المعرفة

uvicorn app.main:app --reload
```

افتح `http://localhost:8000`. للتأكد إن كل حاجة مظبوطة: `http://localhost:8000/api/health`.

> `data/knowledge.json` المرفق **بذرة صغيرة** فيها معلومات متحقق منها بس. لازم تشغّل `ingest.py` قبل الإطلاق، وإلا البوت هيقول "مش متأكد" في أغلب الأسئلة — وده سلوك مقصود.

## بنية المشروع

```
app/
  main.py         FastAPI: /api/chat (SSE) + /webhook (ماسنجر) + الملفات الثابتة
  retriever.py    تطبيع عربي + BM25 + قاموس مرادفات عامية
  prompts.py      البرومبت + فلتر الأرقام
  groq_client.py  اتصال Groq (streaming و non-streaming)
  facebook.py     تحقق التوقيع + Send API
  config.py       قراءة .env
scripts/ingest.py  زاحف الموقع → data/knowledge.json
public/            الواجهة + widget.js للتضمين في الموقع الرسمي
data/              قاعدة المعرفة + سجل الأسئلة بدون إجابة
```

### ليه BM25 مش embeddings

قاعدة معرفة بحجم موقع الجامعة (مئات المقاطع) البحث المعجمي فيها أدق وأرخص وبيشتغل offline. الأهم إن العربي محتاج تطبيع قبل أي بحث: من غيره "الاسكندريه" و"الإسكندرية" توكنين مختلفين. ده متعمل في `retriever.py`.

لو القاعدة كبرت فوق ~2000 مقطع، ضيف embeddings (Cohere `embed-multilingual-v3` أو BGE-M3 محلياً) ودمج النتيجتين بـ RRF.

## التضمين في الموقع الرسمي

سطر واحد قبل `</body>` في `anu.edu.eg`:

```html
<script src="https://bot.anu.edu.eg/widget.js" defer></script>
```

بيحقن زرار عائم يفتح المحادثة جوه `iframe` — معزول تماماً عن الـ Bootstrap بتاع الموقع فمستحيل يكسّر أي حاجة في الصفحة.

## قبل الإطلاق الرسمي

- [ ] `python scripts/ingest.py` واتأكد إن الأرقام الحساسة (مصاريف، مواعيد) اتسحبت صح
- [ ] `ALLOWED_ORIGINS` على دومين الجامعة بس
- [ ] HTTPS + دومين فرعي رسمي (`bot.anu.edu.eg`)
- [ ] cron أسبوعي: `0 3 * * 1 cd /srv/anu-agent && .venv/bin/python scripts/ingest.py`
- [ ] موافقة مكتوبة من إدارة القبول على نص إخلاء المسؤولية الظاهر في الواجهة
- [ ] مراجعة بشرية لأول ~100 محادثة قبل الفتح للعامة
- [ ] تقرير شهري من `data/unanswered.jsonl` لإدارة القبول
